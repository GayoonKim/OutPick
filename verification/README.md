Backend에서 같은 회차의 실제 게시 완료·iOS 재조회 가능 시점을 전달받은 뒤에만 실행한다. 기존 target/login 경로 및 groupID 외에 `OUTPICK_BRAND_LOCAL_ROUND`, `OUTPICK_BRAND_LOCAL_BRAND`, `OUTPICK_BRAND_LOCAL_PUBLICATION_EVIDENCE`(완료 근거 파일 경로)를 주입한다. 실행기는 회차 일치·근거 파일 존재/비어 있지 않음·SHA를 확인하고 근거 내용/관리자 DTO는 복사하지 않는다. 파일 존재는 게시 업무 성공의 자동 판정이 아니며 담당자 인계 대조가 선행한다. `verification/brand-operations-publication-preparation.json`의 Node4는 입력 누락·단계 혼합·빈 근거·대상 부재를 접속 전에 거절하는 준비 검사다. 기존 local-consumer33은 준비/회귀이고 서버 게시 후 통합 결과가 아니다. 접수/중복·reviewing 검사 재실행 없이 --published 메서드만 선택한다.

Backend 소유 로컬 회차의 실제 Firebase SDK 검사는 `brand-operations-local-sdk-preparation.json`(격리/대상 검사4), `brand-operations-local-sdk.json`(초기 접수·중복·내역1), `brand-operations-local-sdk-followup.json`(웹 처리 후 조회1)으로 구분한다. 초기 접수 게이트는 웹 처리 후 재실행하지 않는다. 후속 게이트는 같은 회차의 target/login 파일 경로와 groupID를 실행 시 주입하며 비밀번호/토큰을 출력하지 않는다. 브랜드 운영의 문구·정렬·날짜 표시처럼 제한된 UI 보완은 `node tools/verification-gate/gate.mjs --project . --config verification/brand-operations-ui.json`으로 해당 Swift4/UI3 selector만 검사한다. 사용자 2026-10-15 지시로 이번 UI 보완에서 ios-migration-all/100만 건 검사는 실행하지 않는다. 이 범위의 통과를 전체 B5/회귀/실제 서버 연동 통과로 확대하지 않는다. 호출·데이터·공개 조건 변경은 해당 기능의 전체 필수 범위를 다시 검토한다.

B5는 `node tools/verification-gate/gate.mjs --project . --config verification/brand-operations.json`으로 검사한다. 실제 SDK 쿼리 소스 조건3개와 앱·테스트 빌드를 포함한 Swift/Simulator selector를 requiredTests로 연결한다. fake/spy의 입력·상태·이동·이미지 경계와 fixture UITest를 검사하며 실제 Firestore Rules/인덱스·Development 연동 및 수동 QA를 대신하지 않는다. 대응과 미검증은 docs/ai/tasks/admin-web-brand-operations의 B5 기록을 따른다. 삭제된 관리자 편집 검사는 기존 전면 제거 소스 검사 3개로 대체하고, 공개 요청 내역을 떠난 뒤의 지연 응답이 이동·오류를 만들지 않는 경계도 확인한다.

브랜드 B1 공개 계약 준비는 Node 24에서 `node tools/verification-gate/gate.mjs --project . --config verification/brand-operations-preparation.json`으로 실행한다. ios-migration-all은 기존 앱 설정 24개 check의 shell/xcode selector·필수 ID 합집합이다. ios-migration-map으로 대응을 확인한다. 결과는 output/verification/{실행 ID}/summary.json과 원본 로그에 저장된다. 필수 누락/skip/0건/실패/환경 미준비를 통과로 처리하지 않는다.

민감정보 검사는 고정 Gitleaks release를 .local/tools/gitleaks에 준비하고 tools/security/gitleaks-lock.json의 checksum과 대조한다. .local/security-policy.json에는 version=1, forbiddenValues, 명시 reviewedBinaryPrefixes를 구성한다. 실제 금지 값은 로그나 커밋에 포함하지 않는다. candidate/index/전송 commit 범위를 각각 검사하며 새 iOS 이관 history 범위는 기존 기준 commit 이후다. 과거 전체 공개 이력은 이번 검사 대상이 아니다.

계약/공용 도구 변경은 manifest의 source와 파일 해시를 리뷰하고 갱신한다. 사본 파일만 바꾸면 integrity gate가 실패한다. 실제 Chrome/Safari·Google/Kakao 로그인은 수동 QA이며 자동 테스트로 대체하지 않는다.
