# ADR-022: 브랜드·시즌·사용자는 공용 스타일 무드 ID를 사용한다

## 상태

accepted

## 결정

- `styleMoods/{moodID}`를 공용 canonical taxonomy로 사용한다.
- 사용자는 비공개 `selectedMoodIDs`, 브랜드와 시즌은 각각 독립된 `moodIDs`를 저장한다.
- 브랜드 무드는 관심 스타일 추천에 사용하고 시즌 무드는 선택적 상세 분류로 유지한다.
- taxonomy는 flat하게 유지하고 `displayGroup`은 선택 UI에서만 사용한다.
- canonical ID는 변경하지 않으며 사용 중인 무드는 hard delete 대신 inactive 처리한다.
- `tagConcepts`, `tagAliases`, 시즌 `tagConceptIDs`는 clean break로 제거한다.

## 이유

- 사용자 취향과 브랜드 분류가 같은 ID를 사용해야 단순한 교집합 query로 설명 가능한 추천을 만들 수 있다.
- 브랜드 전체 무드와 특정 시즌의 표현은 의미가 다르므로 같은 필드로 합치면 정보가 손실된다.
- 모든 import 시즌에 수동 무드를 강제하면 관리 비용이 지나치게 커진다.
- 초기 단계에는 결정적 규칙 기반 추천이 데이터와 UI를 검증하기 쉽다.

## 트레이드오프

- 브랜드·시즌·사용자 저장 경로에서 무드 ID 참조 정합성을 서버가 검증해야 한다.
- 다중 무드 query의 결과를 앱에서 중복 제거하고 안정적으로 정렬해야 한다.
- inactive 무드가 기존 문서에 남아 있을 수 있어 표시/편집 정책이 필요하다.

## 보류한 대안

- 브랜드 무드만 두고 시즌 무드를 합치는 방식은 시즌별 스타일 변화 표현을 막아 선택하지 않았다.
- 계층형 taxonomy는 초기 선택 UX와 운영 복잡도가 커 flat v1 이후로 보류했다.
- AI 기반 시즌 무드 자동 분류는 학습/검증 데이터와 운영 검토 계약이 없어 범위에서 제외했다.

## 재검토 조건

- 시즌 무드 데이터가 충분히 쌓여 개인화에 사용할 때.
- flat taxonomy만으로 탐색 충돌이 반복될 때.
- 무드 자동 분류의 ground truth와 관리자 review loop를 별도 설계할 때.
