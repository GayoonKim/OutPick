## 해석·추천

1. **이번 관측으로 브랜드 병렬화의 큰 처리량 이점을 확인하지 못했다.** P6는 S6보다1.66% 짧았으나 A 완료는0.84% 늦었다. B 시작 대기는117.68→53.38초로 줄었지만 접수 후 완료는144.95→146.29초로 빨라지지 않았다. 작업 시작과 완료 효과를 구분해야 한다.
2. **시즌 제한 해제는 권하지 않는다.** Sall의1.49% 시간 차이에32건 추가 다운로드가 있었고, Pall은 더 느리면서239건 추가 다운로드·90.24% 최고 메모리를 보였다. 시즌6이 수학적 최적값이라는 증거는 아니지만 유지할 실측 근거가 추가됐다.
3. **변환1을 유지한다.** T2는 이1CPU/2GiB·실행 순서에서 메모리 안전 조건을 넘었다. 모든 환경에서 변환2가 실패한다는 뜻은 아니며, 이번 자원/입력에서 늘릴 근거가 없다.
4. **다운로드4를 우선 유지한다.** 다운로드8은 실제 사용됐지만 시간 차이1.50%로10% 개선 기준에 못 미쳤다. 메모리 최대도 높았으나 같은 프로세스 잔류·순서 효과와 분리하지 못했으므로 증가 원인을 다운로드 증량 하나로 단정하지 않는다.
5. **업로드8 효과는 미검증이다.** 완료된 본 회차는 업로드 최고2~3개여서 한도4를 다 쓰지 않았다. 증량 효과가 없다고 확정할 수는 없으며 U8을 통과/동률로 처리하지 않는다.

사용자가 선택한 단순 FIFO 요구사항을 반영하면 **브랜드 순차·내부 시즌6·다운로드4/변환1/업로드4·재사용128MiB**를 제품 연결의 유지 후보로 추천한다. 자동 제품 반영은 하지 않았다. 각 설정1회·모두 동일 instance `4cb08cb8-e217-4284-bfa9-0be8f986e994`·고정 순서이므로 최적값/실패율 개선/5쌍 반복 악화/통계적 유의성/10% 채택 판정은 하지 않는다.

성공 본 회차의 CPU 시간은245.61~252.94초, 변환 작업 누적234.44~242.93초로 전체 처리245.29~253.22초와 가깝다. 이 입력은 CPU/변환 비중이 크다는 해석을 뒷받침한다. 병렬 단계의 누적 시간은 합산해 전체 시간을 계산하지 않는다.
