# 대용량 P4 비재사용 대조군 준비 측정

2026-10-03. 사용자의 “이해 완료 다음 핵심 작업 이어서 진행하자”에 따라 직전 추천한 P4/off 대조군1회를 진행한다. [직전7회 결과](phase-3-large-input-design.md)는 P4/128·256 성공, U4조건과P4/512 메모리 중단이다. U/off가 완주하지 못해 같은P4의 유효한 비재사용 기준 시간이 필요하다.

## 승인 범위·비교 계약

- 대용량635MiB 합성 보관 수요/6개 독립job/원본 후보792개/고유 본문786개+커버6개를 유지한다. derived input digest `920ce1c766e9fdfb6ff0e6b4ec2c211f5b1454353a93316d8348a2035f51948e`와 고정 JPEG golden을 변경하지 않는다.
- 단일 준비 회차 `large-control-P4-off-1`, `largeControl:p4-off-prepared-v1`. 기존7회 행렬에 넣지 않고 별도 계획/결과/디렉터리로 보존한다.
- **P4의 시즌당4개·입력 시즌 우선 변환·커버 선준비를 유지하고 해시 원본 cache만 끈다.** 기존128/256의 커버 준비 시점과 같게 유지해 재사용만 바뀌도록 한다. cache가 없는 것과 커버를 선준비하지 않는 것은 별도 설정이다. 이전 U/off는커버 선준비도 꺼져 있어 그 조건과 동일 설정이라고 하지 않는다.
- 공용 다운로드4/변환1/업로드4/경로 저장 제한 없음, 최대6시즌, 최초 포함5회 시도 계약 유지. 새 네트워크 재시도·시간 제한 없음.
-1CPU/2GiB·swap추가 없음·network none·읽기 전용 원본volume·새 컨테이너·무결성 사전 확인 이후 측정. cold-cache라고 표시하지 않는다.
-100ms 표본·500ms 초과 환경 미검증 중단·85% 이상1초 지속 중단 유지. 메모리/환경 중단도1회 분모에 포함하고 자동 재실행하지 않는다.
- 성공 시 예상 읽기1,584회/1,338,062,791B, JPEG1,584개/250,182,505B, 경로792건, reused0·prepared cover6·cache null. 실제 Storage/Firestore 대신 로컬 대체 저장이다.
- 예상 순수 처리 약4분은 앞선 완료조건221~225초를 참고한 추정치다. 빌드·필수 게이트·사전 확인 시간은 별도다. 추가5쌍 본 비교·새 구조·Development·제품 기본값 변경은 이번 실행에 포함하지 않는다.

## 변경 파일·검증 계획

1. `large-comparison.ts`: `makeLargeControlPlan`, 기존7회와 구분한 단일 계획/집계. `reuse-comparison.ts`: marker 기반 엄격 계획 검사. `reuse-contract.ts`: cache on/off와 별개로 명시적 arm의 커버 선준비 수를 확인한다. 기존 계획의 기대값은 그대로다.
2. `large-input.test.ts`: 신규3개—계획 변조/기존7회 혼입 거절, 실제 작은JPEG84개와114회 읽기/본문 재다운로드/커버 선준비/반환, 큰 입력 집계 가짜 사건의1,584회 읽기·중단 분모·거짓 성공 거절. 실제 픽셀 검사와 집계용 가짜 기록을 구분한다. 실패/취소/형제 작업 반환은 기존 필수 회귀도 함께 실행한다.
3. `verification/lookbook-import.json`/로컬 Linux 설정에 신규 필수3개 연결. 전체250개·필수142개가 목표이며 실행 결과 없이 통과로 처리하지 않는다.
4. 전용 `run-p4-off-control.mjs`는 새 원본/manifest/시각/이미지/게이트/driver digest/외부 종료/log/정리를 기록한다. `analyze-large-input.mjs`로 독립 재집계한다. 완료 여부와 관계없이 실제 중단 증거·부분 처리를 남긴다.

공용 연결 검증 파일이 겹쳐 순차 구현하며 새로운 DI/API/Firestore 변경은 없다. 기존 SourceBufferStore/P4 scheduler/실제 변환·업로드 구현을 변경하지 않는다. 신규 UI가 없어 수동 화면 QA는 해당하지 않고 실제 원격 QA는 Development에 남긴다.

## 완료 후 판단

P4/off·128·256을 다음 반복 비교의 후보로 좁히고,512와 U의 실패 조건을 다시 반복하지 않는다. 추천 규모는 동일 이미지에서3조건×5회=15회로 기존5쌍 기준을 적용하는 것이다. 현재약220~225초 기준 순수 처리약55~56분은 추정치이며 게이트/사전 확인은 별도다. 새15회는 아직 확정/실행하지 않았다.

과거 준비1회씩을 새5쌍에 합치지 않는다. 조건/순서를 고정한 반복 비교로 정확성·실패/중단·전체/첫 시즌 반복 악화·읽기/메모리 여유를 판단한 뒤 실제 job 계약과 Development 단계로 넘어갈 후보를 선택한다. 이 결과만으로 최적 예산/10% 개선/반복 실패율을 확정하지 않는다.
