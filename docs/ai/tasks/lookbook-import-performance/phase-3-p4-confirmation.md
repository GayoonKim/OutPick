# P4 재사용 예산 다섯 쌍 로컬 확인

사용자의 “다음 핵심 작업 진행”으로 직전 제안한 P4/off·128·256MiB 각5회, 총15회 비교를 승인받았다. [단일 대조군 준비 결과](phase-3-p4-off-control.md)와 과거7회는 이번 표본에 포함하지 않는다. 본 문서는 승인된 실행의 조건·변경 파일·검증·결과 진입점이다.

## 비교 조건과 완료 기준

- 기존635MiB 합성 수요/6개독립job/후보792개/고유본문786개+커버6개/같은원본·golden·derived digest를 유지한다. 정상회차 JPEG1,584개/출력250,182,505B/경로792건이며15회 전부성공 시 JPEG23,760개/출력3,752,737,575B/경로11,880건이다.
- 전 조건 P4:시즌당4개, 준비된 변환의 입력시즌우선, 커버 선준비, 공용다운로드4/변환1/업로드4/경로제한없음, 시즌최대6개. 차이는 해시원본 보관 예산 off/128/256MiB뿐이다.512와 U는 이번후보에서 제외한다.
- 새 고정Linux ARM64 Docker이미지 하나로15회를 모두 수행한다. 매회 새컨테이너,1CPU/2GiB/추가swap없음/networknone/읽기전용원본volume. 무결성 사전 확인 후부터 측정하며 cold-cache라고 하지 않는다. 실제네트워크/Firebase트래픽은 발생시키지 않고 로컬읽기·실제sharp·대체업로드/경로저장을 사용한다.
-100ms표본,500ms초과환경미검증중단,85%이상1초지속메모리중단 유지. 메모리중단도 해당5회 분모에 남기고 정리 후 다음 독립조건을 진행한다. 환경/정합성/정리실패는 나머지미수행, 자동재실행/실패표본교체없음. 시즌최초포함5회시도계약 유지.
- 예상 순수처리약55~56분이며 빌드/게이트/사전확인·분석은 별도다. 원격비용/Development실행/제품기본값변경은 포함하지 않는다.

## 판정

- 정확성·복구·실패/중단분모를 우선 확인한다. 성공시각은 모든파일/경로완료와 자원정리 기준이다.
- 조건별5회 전부완주할 때 전체/첫시즌/읽기량의 중앙값을 표시한다. 중단조건의 성공분만 뽑아5회 성능이라고 표시하지 않는다. 실행된 성공+실패+중단 중 실패/중단 비율을 관측치로 기록하고 미수행·환경미준비는 별도표시한다. 모집단의 실제실패확률이라고 주장하지 않는다.
- 양쪽모두5회완주일 때만 전체/첫시즌 반복악화 판정:5쌍 중3쌍이상10%느리고 중앙값도10%느리면 채택보류. 불완전쌍은 판정null로 남긴다. 이 기준은 실험조기중단기준이 아니다.
- 전체중앙값10%이상단축과 첫시즌반복악화없음을 로컬속도우선기준으로 표시한다. 조건을충족해도 실제원격성능이나 제품최종채택을 자동확정하지 않는다. 시즌별완료시각도보조기록하고 메모리최고치와캐시·논리Buffer를단순합산하지 않는다.
- 결과가비슷하면 단순성·메모리여유·읽기량을근거로후보를추천한다. 미확정인실제job리뷰/수동재시도계약과 Development설계는 이후단계다.

### 읽기 절감과 정합성

- 정상 완료 시 off는1,584회/1,338,062,791B,128은1,430회/1,203,872,831B,256은1,284회/1,069,662,146B를 로컬에서 읽었다. 완주 계약 기준 읽기 바이트 절감은128에서10.029%,256에서20.059%다. 이는 읽기량 비교이며5쌍 속도 개선 또는 실제 네트워크 절감 실측이 아니다.
- 128의5회 모두 cache hits154/misses632, 최고 보관134,189,960B였고 예산 거절637건으로 부분 재사용 압박 조건이 성립했다. 256의 성공3회는 hits300/misses486, 최고 보관268,400,645B/예산 거절490건이다. 해시 원본 보관량과 현재 입력/출력의 논리 Buffer 최고치를 단순 합산하지 않는다.
- 성공11회는 JPEG17,424개/2,752,007,555B/경로8,712건의 golden·trace·계약 일치를 확인했다. 각 성공 회차는 JPEG1,584개/경로792건이다. 중단 회차의 부분 산출물은 성공 총량에 포함하지 않는다.
