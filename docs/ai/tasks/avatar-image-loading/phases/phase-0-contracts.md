# Phase 0 — 호출 지도와 기술 계약

2026-09-18 후속 결정: 필요 시 백그라운드 재인코딩 승격(D10), 썸네일 다운로드3MiB 통일(D11) 확정. 원본-only 자료는 정상 업로드가 아니고 실제 존재 미확인이므로 필수 선행 결정에서 제외. 아래 비교 목록은 최초 조사 기준이다. JPEG/PNG는 실제 표본 비교 후 서비스에 주입하며 공용 기반은 형식을 고정하지 않고 구현한다.

## 목표

확정 정책을 바꾸지 않고 실제 소비자·표현·캐시/세션 경계를 매핑해 후속 코드 변경을 구체화한다.

## 변경 범위와 순서

1. AvatarImageManaging 호출을 제품 화면·preview/test로 구분한다. Chat/Profile/MyPage/Lookbook의 Container·Coordinator를 따라 사용처 정책 출처를 기록한다.
2. AvatarImageSource, UserPublicProfile, ChatProfileSyncManager, CommentAuthorProfileStore, CurrentUserSessionStore/JoinedRoomsSessionStore의 경로 최신화·nil 제거·참여 여부 전달을 확인한다.
3. pipeline의 memory fast path·payload 소유권, ImageViewer provider fallback·참조 수명, 아바타 maxBytes 소비처 차이를 조사한다.
4. 구현 전 기준 git HEAD/관련 설정/대표 QA 경로를 기록한다. 사용자 데이터 삭제 없이 가능한 warm/first-view 구간부터 구분한다.
5. 계약과 예상 변경 파일을 design/결정 상세에 보완한다. 제품 영향이 있는 선택은 사용자와 먼저 논의한다.

## 구현 전 논의가 필요할 수 있는 사항

- **메모리 적중 후 디스크 승격:** 현 메모리에는 UIImage만 있어 압축 원본 바이트가 없다. 재인코딩(추가 CPU·표현 변화), 압축 바이트 추가 보관(메모리 증가), 저장용 재다운로드(네트워크 증가) 중 실제 가능한 방식/예산을 비교해 결정한다. 무비용 승격이 이미 가능하다고 가정하지 않는다.
- **동일 요청 한도:** maxBytes가 다르면 기존 병합 identity가 다르다. 기존 서비스별3/5MiB 등 사용값을 표로 확인하고 썸네일/원본별 정합성을 결정한다. 이번 승인으로 다운로드 한도 상향을 임의 확정하지 않는다.
- **썸네일 경로 없는 자료:** 원본 대체 일반 표시와 원본 무캐시 정책의 교차를 확인한다. 원본을 일반 썸네일 디스크로 저장하지 않도록 표시용 표현 변환/비저장 대체 중 필요한 결정을 논의한다.
- **정책 진입점 누락:** 출발 정책이 없는 직접 프로필 진입이 실제 있으면 누락 경로와 대안을 보고한다. 추정 참여 여부로 디스크를 허용하지 않는다.

## 완료 기준·검증

제품 소비자별 파일·사용처·경로·한도·저장 정책·최신화·취소 지도가 있고, 위 해당 기술 결정이 다음 phase를 구현할 만큼 구체적이다. 기존 기능/서버 계약 변경 없음. 이 phase는 읽기와 문서화로 진행하며 테스트 실행 없이 호출 경로·문서 링크를 확인한다.
