## 배경과 확인된 사실

- 2026-09-16 iPhone 14 OutPick-DEV의 `미디어 QA`방에서 과거 사진은 첫 방문에 느리게 표시됐고, 같은 사진을 한 번 표시한 후 방에 재입장하면 바로 표시됐다(사용자 수동 QA).
- 현 코드에서 채팅 썸네일 요청의 `chatThumbnailMaxBytes`는 300,000,000바이트다. 큰 파일을 허용하는 다운로드 경로가 네트워크 전송 중 디스크 I/O의 쓰기 1개 슬롯을 점유한다. 앱 계측 구간의 네트워크 활성 최대값은 1이었지만 구간에 다른 화면 조작도 섞여 있어 방의 사진별 지연 원인과 바이트량은 별도 재측정이 필요하다.
- 업로드 썸네일은 원본 해상도를 유지할 수 있고 최대 300MB까지 허용한다. 룩북의 작은 썸네일과 동일한 크기·캐시 정책으로 간주하지 않는다.

## 사용자와 합의한 방향

- 화면 근처의 채팅 썸네일을 선로딩한다.
- 사용자가 방문한 원본 사진·영상만 용량이 제한된 디스크 캐시에 보관한다. 방의 모든 원본/영상을 자동으로 내려받는 방향은 채택하지 않았다.
- 이번 `image-loading-stage-concurrency` Phase 5의 완료 조건에서 분리한다. 현재 기록은 후속 논의 대기이며 구현 승인 또는 세부 구현 계획이 아니다.
