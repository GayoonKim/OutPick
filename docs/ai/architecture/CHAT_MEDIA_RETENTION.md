# 채팅 미디어 7일 만료 — 최종 계약과 검증

2026-10-01 기준, 합의된 구현과 개발 환경 QA를 완료했다. 사진·GIF·영상의 원본과 썸네일에 같은 보관 기한을 적용한다. 이 문서는 중간 설계의 SDK 직접 읽기·만료 팝업·영상 전용 URL 정책을 대체하는 최종 기준이다. 운영 배포는 별도 범위다.

## 서버 확정과 접근

- 서버가 contract 3 전송을 확정할 때 `sentAt`과 `mediaExpiresAt = sentAt + 168시간`을 보장한다. 메시지, mediaIndex, delivery job, expiry job을 같은 Firestore transaction에 기록한다. 전송 예약·로컬 촬영 시각을 기준으로 삼지 않는다.
- 원본과 썸네일은 각각 bucket/path/generation을 가진다. 메시지·실시간 응답·로컬 GRDB·답장 미리보기까지 필요한 만료 메타데이터를 보존한다. 로그인·다운로드·캐시 사용은 기한을 연장하지 않는다.
- `issueChatMediaURL` 입력은 roomID/messageID/attachmentID와 original 또는 thumbnail이다. App Check·인증·계정 열람 권한·방 상태·메시지 공개/삭제 상태·첨부 소속·정확한 generation·미만료를 서버가 검사한다. 기존 `issueChatVideoPlaybackURL`도 유지한다.
- 모든 채팅 미디어는 HTTPS 서명 URL을 사용한다. 수명은 최대 1시간이며 미디어 만료보다 늦지 않다. ready 버킷 SDK 직접 읽기는 거절한다. URL은 앱 메모리에만 보관하며 디스크 캐시 키로 사용하지 않는다.
- 이미 발급한 링크는 수명 동안 사용할 수 있다. 계정 상태나 메시지 숨김 변경을 이미 발급된 링크에 즉시 반영하는 보장은 없다. 원본 삭제 또는 URL 만료 후 새 요청은 거절된다.
- 미배포 앱의 최종 계약으로 시작하므로 contract 1/2를 새 메시지로 확정하지 않는다. 구형 worker completion은 실패·객체 정리로 수렴한다.

## 정리와 신고 증거

- `chatMediaExpiryJobs`는 클라이언트 접근이 금지된 작업 원장이다. 시간당 1회 실행하며 7일 시점의 접근 차단과 실제 파일 정리는 분리된다. 정리 실패·보류로 물리 삭제가 늦어져도 기한은 연장하지 않는다.
- 한 실행에서 최대 3회 즉시 삭제를 시도한다. 성공 객체는 제거하고 실패 객체만 다음 정기 실행에서 다시 처리한다. lease 만료 작업을 회수하고 대상 generation만 삭제한다. 같은 경로의 새 generation을 삭제하거나 이전 삭제 성공으로 간주하지 않는다.
- 신고 증거 복사가 진행 중이면 원본 정리를 보류한다. 복사 완료 또는 terminal 실패 후 정리 가능 상태로 돌린다. 만료된 미디어로 새로운 증거 준비는 시작하지 않으며 기존 신고 receipt 재조회는 유지한다.
- 전체 객체 삭제 성공 시 작업 문서를 제거한다. 별도 완료 기록 문서는 생성하지 않는다. 메시지 자체와 기존 크기를 표시하는 메타데이터는 유지한다.

## 앱·캐시·사용자 흐름

- 계정·path·generation·만료 시각을 캐시 리소스에 묶고 hit, write, 원본 lease 취득과 늦은 완료에서 확인한다. 앱 시작·활성화 시 로그인 전에도 전 계정 만료 캐시를 정리한다. 앱이 실행되지 않는 동안 iOS 파일의 정각 삭제를 보장하지 않는다.
- 오프라인에서는 로컬 메시지·미만료 캐시만 사용한다. 이미지가 없으면 기존 크기의 기본 이미지를 표시하며 서버 조회·메시지 재시도 버튼은 억제한다. 연결 복귀 후 기존 조회 흐름을 재개한다.
- 만료된 메시지는 채팅에서 칸 크기를 유지한 기본 이미지로 보인다. 탭하면 사진·GIF·영상 모두 기존 전체 화면을 열어 기본 이미지와 **“미디어 저장 기간이 만료되었어요.”**를 표시한다. 원본 다운로드·재생·저장은 차단하며 닫기와 사진의 기존 좌우 이동은 유지한다.
- 열려 있는 미디어도 기한 도달·백그라운드 복귀 때 픽셀·재생 버퍼·lease를 제거한다. 답장 대상은 닉네임·종류/개수와 유효 썸네일 또는 만료 아이콘·상태를 표시한다. 방 설정의 사진·영상 목록에서는 만료 항목을 제외한다.
- 영상 URL만 만료되면 1회 갱신하면서 위치·재생/일시정지 의도를 복원한다. 일시정지 중에는 재개·seek 때 갱신한다. 실패 후 수동 재시도하며 미디어 7일 만료가 우선한다.
- 원본 다운로드는 실제 만료 응답과 URL 기한을 함께 확인해 1회 갱신한다. HTTP 400 ExpiredToken과 명시적인 만료 403을 일반 400/권한 403과 구분한다.
- 화면 닫기·계정 전환·삭제 뒤의 URL/파일 응답은 취소·세션 검사로 거절하고 임시 파일을 정리한다. Photos 제출 전에는 만료·취소를 검사한다. 이미 OS에 제출한 저장은 완료 콜백까지 파일을 보존하고 닫힌 화면에 늦은 결과를 표시하지 않는다. 사용자가 Photos에 저장한 사본을 7일 뒤 삭제하지 않는다.

## 검증 범위

프로그램 판정은 [검증 운영 기준](PROGRAMMATIC_VERIFICATION.md)의 다섯 설정을 사용한다. 실행기 원본은 `tools/verification-gate/`에서 관리하며 공용 설치본으로 로컬 실행했다. GitHub CI 연결은 포함하지 않는다. 필수 ID 누락·skip·0개 실행은 통과로 처리하지 않는다.

PR 정리 시 다섯 게이트를 재실행해 모두 passed, 실패·차단·필수 누락 0을 확인했다. iOS 만료 설정은 28개 suite이며 실제 Simulator Photos 검사도 포함한다.

## 개발 원복과 운영 전제

- 임시 서버 120초 정책·환경변수는 제거하고 최대 3600초/min(media expiry)로 복원했다. 새 URL 약 3599.4초, GET 200·Range 206을 관측했다. 이는 1시간 **발급** 확인이며 실제 1시간 대기 시험은 아니다.
- 앱의 DEBUG QA 도구와 회귀 검사는 유지하되 일반 DEV 실행에서는 비활성이다. iPhone 일반 실행 및 Simulator 서명 DEV 실행을 복구했다.
- 전용 서명 계정은 환경별 1개이며 Functions 실행·서명을 담당한다. ready 버킷 읽기와 기본 Firestore DB 조건부 읽기를 사용하고 쓰기·삭제 권한은 부여하지 않는 경계다. 청소 계정은 분리한다. Admin SDK는 Rules를 우회하므로 IAM 경계가 필요하다.
- 개발 ready 버킷의 PAP enforced·UBLA·soft delete 0 및 관련 IAM/Rules/index/Functions/Socket 배포를 검증했다. 운영 프로젝트의 같은 준비·배포는 이번 완료/머지에 포함되지 않는다.

### QA 도중 로컬 초기화와 복구

QA 폴더 정리에서 `devicectl copy --remove-existing-content true`의 범위를 잘못 판단해 iPhone 앱 로컬 데이터가 초기화됐다. 하위 폴더만 삭제된다는 이전 판단은 철회했다. 이 옵션을 앱 하위 폴더 정리 용도로 다시 사용하지 않는다.

초기화 후 DEV App Check 디버그 토큰 문제는 사용자 승인으로 현재 기기의 토큰 1개를 등록해 복구했다. 기존 토큰 삭제·운영 설정·검증 강제 정책 변경은 없었다. 서버 인증/앱 검증 성공과 일반 앱 실행, 원래 계정의 서버 메시지·썸네일 재동기화·만료 안내·사진 확대/저장을 확인했다. 서버에 없는 로컬 전용 설정·미전송 데이터까지 복원됐다고 주장하지 않는다. 원본 로그와 토큰은 공개하지 않는다.
